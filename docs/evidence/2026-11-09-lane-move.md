# Lane move implementation acceptance — 2026-11-09

Batch B adds the CLI-only `lane-move` operation in `lanemove.py`. Its base is
public main `3d1aa78` (roster identity and observed senders, PRs #4 and #5).
`lane.py` remains the agentctl watcher; the new module uses its event writer.

Owner rulings implemented:

- Stop is verify-only. The move has no kill, signal or stop-command path.
- `--apply` authorizes copying the parent session JSONL after quiescence. Source
  retention, receipt-first SHA-256 checks and exclusive publication prevent
  replacement of a conflicting destination.
- The manifest lane changes only under apply, with a private backup and hashes.
  Other TOML values survive; unsafe isolation and concurrent lane edits refuse.
- Operator resume is the default. Only `resume="headless"` launches Claude;
  account/session locks and durable launch intent prevent a repeated automatic
  launch after an uncertain outcome. The copy and source are checked again
  immediately before that launch.
- Before/after observations use `usage.collect` and the roster identity contract
  (configuration path, directory-name account label and observed parent model).
  No accounts probe or Batch C implementation is included.

Recovery evidence is entirely synthetic. The regression tests cover freeze ask
acknowledgement, older open obligations, holders and failed probes, transcript
idleness, session/move locks, destination conflicts and symlinks, checksum
mismatch, source changes, crashes after copying, after a manifest rename and
after phase publication, uncertain resume outcome, reappearing holders, stale
listening evidence, fresh destination hooks, multiple sequential moves and
cross-manifest plan rejection. An executable fake Claude verifies argv, cwd,
configuration environment and successful hook-based re-arm; it exits naturally.
All new tests prohibit process signalling.

Operational decisions: an omitted mode means plan; the freeze ask itself must be
acknowledged before apply advances. `--timeout` bounds each polling stage and
`--idle-seconds` sets the minimum transcript quiet age. Completed move receipts
are retained and repeating an unchanged completed move is a no-op. An uncertain
launch requires operator inspection/re-arm rather than automatic retry. These
are documented in the README LANE-MOVE section and generated OPS reference.

No real account/configuration directories, bus state or services were changed.
No PR or merge was requested. The outcome is recorded here rather than writing
to live ANX state, following the task's explicit no-live-state boundary. No GCP
tier was used.

Validation uses disposable HOME, XDG state and coordkit state directories on the
scratch volume, with the repository fake tools. The default 0.300s cold-hook
assertion failed once during a full run at 0.669s and on its documented isolated
rerun at 0.307s. Final full-suite validation uses the documented CI setting
`COORDKIT_COLD_CLI_BUDGET=1.0`; the assertion stays enabled and hook code is
unchanged. This timing-budget adjustment is the validation deviation.
