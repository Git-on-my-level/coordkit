# Failure contracts

These invariants guide tests and review. Each blocking state needs an entry, a normal exit, a maximum age, and an escalation owner. `tests/state_registry.py` records those lifecycles; the scanner is a review fence rather than a formal proof.

| # | Invariant |
| --- | --- |
| 1 | Every latched or blocking state has a named exit and a max age. When an object exceeds its max age, it is either dispositioned (an explicit `quarantine`/`abandon` with a reason) or escalated. One stuck item must never hold the whole verdict |
| 2 | A stuck or failed state that needs a human must create an ANX ask (through a validated decision brief). Logs never count as an alarm |
| 3 | A loop run that cannot start (lock held, previous run alive) is recorded as a failed or skipped receipt, never a silent no-op. Every run has a hard deadline, enforced by a timeout that kills the run, and a lock whose owner exceeded the deadline is broken and reported |
| 4 | Declared and installed state must be compared. Installed launchd jobs, plists, PATH, hooks and ANX board/cards are diffed against the manifest. Drift fails doctor and is reported by the reconciler, never silently overwritten |
| 5 | `unknown`/`unmeasured` is a state with its own counter and exit. N consecutive unknowns escalate exactly like failures. No state machine may make progress only on a "clean" signal |
| 6 | Queues expose a stock, not just a rate. The reconciler reports the count and age of open obligations by kind (open rulings, unacked asks, leases, mirror lag, dead letters), plus a threshold per kind |
| 7 | Every marker or lease written on an enter path has a matching clear on the normal exit path. A TTL is only the backstop, and tests assert the clear |
| 8 | Rollback and `down` must work from any drifted state. They act on what is installed, not on what the manifest says should be installed |
| 9 | Shared state that one actor can corrupt for all is watched, and agents never export repository-selecting git env into child processes. The reconciler reads each shared git dir's config **as a file** (a set core.worktree redirects `git -C` itself) and files an ANX ask the first time `core.worktree` appears. Launch briefs say: run tools from the worktree (`cd`), never `GIT_DIR=`/`GIT_WORK_TREE=` |
| 10 | A lane past `max_run_hours`, or whose run agentctl cannot reach for `hung_after` (2h), is expired (cancel, fail, lease to the lead, ask), and a failed lane's card moves back to `ready`. Shadow comparison applies the same configured deadlines, so a hung execution never counts as progress |
| 11 | A safety mechanism's mode is a ruling with its own effective time, not a side effect of another milestone. When a ruling changes what an automatic actor may do, the change applies at ruling time, the actor reads it on every tick, and the actor's current mode is visible and diffed against the latest ruling. An automatic action that contradicts a recorded ruling is a doctor failure and an ANX ask |
| 12 | Every waiting state has an age-based sub-state (`waiting` to `overdue`) with a deadline stamped at entry, a dwell metric, and an exit (escalate, reprioritize or terminal outcome). Backfill never shares a queue lane with fresh work without priority, and health metrics count by age, not only by a status flag that a stuck row never sets |
| 13 | Alert-only is a mode of a running watcher, not an exit. While the condition holds, the watcher keeps running and re-alerts on a cadence (with dedupe), and a STOP it writes is itself a stuck state with a max age and an ask. "Silent because it fired once" is a failure |
| 14 | A config with one applier needs a readback that the applied value matches the declared one, and an applier that errors N runs in a row escalates. Editing declared config is not done until the readback shows it applied |
| 15 | A trip records the objects that caused it and clears when those objects are dispositioned, not only when they age out. Re-arming an actuator checks for an unresolved trip first and refuses or requires an explicit disposition, so it never re-fires on stale evidence |
| 16 | One fact has one owner record. When two records must agree, the transition that completes one commits the other in the same transaction, or a reconciler finds disagreeing pairs by age and repairs or escalates them |
| 17 | A retry loop has an attempt cap, a backoff, a demotion to a slower lane after N failures, and a terminal state (dead letter with a reason). A budget cut counts as an attempt |
| 18 | Listening is a renewable lease with a hard per-iteration deadline, never "process/pane alive". A send to a recipient with no live lease is `recipient_deaf` and escalates at once to a declared fallback (urgent uses a shorter deadline). A role with no live member is an alert to the configured relay, never a silent copy. Any addressed ask unacked past 5m (urgent) / 15m escalates whatever the waiter state. Typed delivery is unconfirmed until an ack or transcript growth; never type over input. Copies are never replies |
| 19 | A review verdict is a record with an enforcement surface: the terminal step writes the ledger and turns BLOCK/FIX-FIRST (and a missing verdict) into a structured hold from the reviewer; merges require a positive SHIP at the exact head rather than the absence of a BLOCK |
| 20 | A gate that reads a list must read all of it or fail closed: paginate every page for the exact head, compare with total_count, never decide green from a first-page rollup |
| 21 | A question is a record with a deadline and a ladder: tier 1 a live agent with authority, tier 2 anx (straight away for guarded classes),  every capture path (modal, prose at turn end, idle notice, transcript sweep) feeds it; answers are delivered to deaf askers and close both ends |
| 22 | A path written into another tree is resolved absolute before writing; a cutover step that edits harness settings runs from a session allowed to, scripted with its own verify-and-rollback so whoever runs it cannot leave a half state |
| 23 | A tool that adopts an existing log starts at the adoption point, never at row 0. The cursor is seeded to the log end at cutover, the mirror projects only rows that coordkit wrote, and obligations count only from `obligations_since`. Rows from another writer are input that can be malformed: skip them and log. Time the first pass on real data before the go |
| 24 | Only `permission_prompt` notifications are captured, and they go to tier 1. A brief gate sits at the single ANX chokepoint (`AnxClient.ask`): a known asker, a title of 12 words or fewer ending '?', 2-4 options with consequences, a recommendation with its reason and the default if nobody answers; ids go to details. A refused ask goes to the tier-1 agent once, never to the operator. the operator's own sessions are never captured |
| 25 | A projection that hits a definite absence dead-letters that one row with its reason and moves on; only transient failures stop it. Toolkit health findings go to an agent, except repeated loop failures: those bypass the bus and reach ANX Decide on the loop card, re-arming at growing manifest-configured intervals until recovery |

Runtime surfaces include reconciliation, loops, addressed routing, review ledgers and question capture. Automated paging and a systemd installer are outside v0.1; integrations must provide their own supervision. The standalone merge helpers retain their gate contracts, but there is no top-level merge CLI command.
