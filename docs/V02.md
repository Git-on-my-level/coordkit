# v0.2 operations and adapter contracts

Python 3.11+, standard library only, on macOS and Linux.

## Operations

[OPS.md](OPS.md) is generated from `coordkit.ops`. Bus parser arguments and MCP
schemas come from this registry; the v0.1 MCP schemas are frozen in a fixture.
The existing orchestration commands remain compatibility entry points for
installations using cards, loops, questions and lanes. New integrations should
use the small adapter interfaces rather than importing that orchestration layer.

## Bus

New records carry `v: 2` and a zero-based physical-line `seq`, assigned under the
append lock. Legacy records normalize to `v: 1` in memory. No migration rewrites
the log. Invalid complete lines are reported and represented by inert rows so
integer cursors keep their positions; malformed hold objects remain visible.
An incomplete final line is retried by tail readers and blocks appending.

Reader cursors, refs, aliases and the harvest cursor live in `state/` beside the
bus log. Old manifest-root cursors and aliases are read for migration. During the
compatibility window, inbox/wait and harvest cursors advance in both locations so rolling
back the wrapper does not replay delivered work. On re-upgrade, readers select the
greatest valid position from either location in memory; corrupt, negative and
beyond-end positions cannot hide work. Only consumption under the cursor lock
and write gate advances both copies. Unmarked harvest never writes cursors.
Mirror state remains under the manifest root. Byte
checkpoints validate inode, size and the preceding boundary before reuse.

Use repeated `--to` flags (or comma-separated names) for multiple recipients.
Each recipient gets one scalar-`to` row. `bus reply ID --from NAME TEXT` posts an
answer to the original sender and acknowledges actionable work. Identical posts
within five minutes print `DEDUPED ID`; `--force` bypasses suppression. FYI and
state latches retain their longer reminder windows.

## Live lanes and wake

Every registered lane is live until explicitly retired. An addressed non-FYI post
to a lane or alias wakes a non-listening live lane; broadcasts never wake.
Reply/answer/ack feedback is suppressed by the shared wake policy.

Claude Code's primary protection is the managed Stop guard: before an interactive
or Remote Control session ends its turn, it must read pending actionable rows and
arm its usual background bus waiter. See [Hooks](HOOKS.md). Recent transcript or
delivery-hook activity is sufficient for delivery during a turn, but cannot stand
in for waiter evidence at Stop.

Headless Claude Code lanes can opt into resume with `resume = "headless"` in their
`[[lanes]]` entry and a pinned `session_id`. The default (absent or empty `resume`)
never permits a Claude resume. `headless` remains an operator assertion that no
interactive process owns the lane. Interactive and Remote Control sessions must
not be marked headless; they rely on their Stop guard and waiter to retain
process memory. The adapter runs `claude --resume SESSION -p PROMPT`
without `--fork-session`, using the lane's cwd and `CLAUDE_CONFIG_DIR`. It rechecks
listening under a shared per-user session lock. Before a new launch, it refuses with
`unresumable` / `holder_present` when any live process has the session ID in its
argv (including `--resume SESSION`) or holds the transcript open. Open-file
detection requires `lsof`, resolved from PATH, then `/usr/sbin/lsof`, then
`/usr/bin/lsof`. An absent tool refuses with `lsof_unavailable`; a failed,
timed-out or malformed probe refuses with `lsof_probe_failed`. These reasons are
stored in the Claude adapter attempt in the wake record.

The lock is keyed by the resolved Claude config directory and session ID, so
different manifests, bus roots and lane names share it. Locks live in
`$XDG_STATE_HOME/coordkit/resume-locks`, or `~/.local/state/coordkit/resume-locks`
when XDG state is unset or relative. The directory is mode 0700 and lock files
are 0600. The lock spans a final holder recheck immediately before launch; kernel
locks release on exit and the small lock files remain for reuse.

The child shell writes its own PID before exec while the session lock is held
across launch. A separate identity record stores process start time; PID reuse
is checked against that time, or a `comm` containing `claude` when no start-time
record survived. A mismatch is stale, and the holder checks still apply. The
detached turn can outlive the wake caller. Only the first five seconds are checked for immediate refusal; later
errors remain in `state/wakes/NAME.resume.log` beside the wake record and PID file.
The lane's existing Claude configuration must permit its headless tools.

The Claude Code adapter runs before agentctl and returns `unresumable` for lanes
it cannot resume, allowing agentctl to try. A listening result stops the adapter
chain. The agentctl adapter is discovered when its executable is available. It
continues the latest execution labelled `coordkit.lane.<lane>` with an idempotent
request key and asks the resumed session to read its entire inbox. `coordkit lane`
launches add that label; other launchers opt in by adding it. The lane name alone
is not enough, because workers a lane launches carry its name too. The continuation
runs in its own process session, so waking never bounds or cancels the resumed turn.

Rows written by another bus CLI bypass the post-append sink. Run
`coordkit wake-scan` on a short interval to apply the same policy to them; it
keeps a byte checkpoint and starts at the end of the log on first run. Wake-scan
ignores unknown top-level tables so an unrelated manifest integration does not
stop delivery. A table whose semantics affect wake behavior must be guarded by
top-level `minimum_coordkit_version = "X.Y.Z"`, which remains fail-closed.
`up` does not install a wake-scan job implicitly.

See [state audits](AUDIT.md) for `audit-state`, optional scheduled audits and
secret-scrubbed transcript processing.

### Scheduled wakes

```sh
coordkit wake-at LANE "check the 2h readback" --in 2h
coordkit wake-at LANE "re-run the gate" --at 2030-01-02T03:04:00Z
coordkit wake-at --list [LANE]
coordkit wake-at --cancel ID
```

A timer is a file under `state/wakes/timers/`. When it is due, the next
`wake-scan` appends one `handoff` row from `coordkit` to the lane (id
`wake-at-ID`, topic `coordkit-timer`) and the ordinary wake path delivers it. It
exists for lanes that cannot hold a timer of their own, such as
[Hermes lanes](HERMES.md), and replaces sleeping shells for everyone else.

- The time must be in the future and within seven days; `--at` needs a zone.
- The row says who set the timer and when, then the text. The whole row must fit
  `[bus] text_cap`; a text that would not is refused when the timer is set. At
  most 64 timers wait per lane.
- The row needs no acknowledgement. It is a `handoff` without a repo reference,
  so with `[handoffs] required = true` an explicit pickup of it is refused like
  any other such handoff; reply to it or simply act on it.
- `--from` names who set it (default `COORDKIT_AS`, else the lane itself).
- Delivery is at least once. A timer whose append did not finish (a crash or an
  error) is tried again five minutes later, with the same row id, and one
  timer's failure does not hold up the others. After twelve attempts it is set
  aside as `ID.failed`; `--list` shows it and `--cancel` removes it.
- Only a live manifest fires timers; a shadow reader leaves them alone.
- `--cancel` refuses (exit 1, `TIMER_FIRING`) while a scan is posting that
  timer's row. A claim older than five minutes is treated as abandoned and can be
  cancelled; a scan that stalled that long and then resumes can still post it.
- Precision is the wake-scan interval. Without a scheduled `wake-scan`, timers
  never fire.
- A timer whose lane was retired meanwhile is dropped without a row.


`[bus] wake_debounce_minutes = 5` is the default. Bus-side `state/wakes/` stores
intent before contacting the adapter, its outcome, and a JSONL attempt journal.
Failures and unavailable adapters also hold the debounce window. A pending
record after a crash is visible and eligible for a fresh attempt after the
window. Unresumable sessions depend on hook delivery while live and their
background waiter between turns. A recorded PID prevents concurrent headless
resumes; Claude resume does not accept the agentctl idempotency key, so a crash
after a completed turn may lead to another inbox check after the debounce window.

`coordkit retire NAME --to OWNER` refuses future posts with an owner redirect.
`coordkit unretire NAME` restores delivery. Aliases resolve before both actions.
Retirement state is shared by writers using the same log.

## Adapters and the relay seam

`coordkit.adapters` defines `HarnessAdapter`, `LauncherAdapter`, and
`MirrorAdapter` protocols. Built-in optional adapters cover agentctl, ANX and
Claude Code. Codex and Hermes report configuration presence only; no hook
installation is implied. Third-party adapters register the `coordkit.adapters`
entry point and are selected by name in `[adapters.NAME]`.

Core owns append locks, cursor advancement, mirror retry/dead-letter state and
wake debounce. Adapters own external commands and projections. The named relay
seam is `notify(manifest, recs)` after the append has been fsynced and its lock
released. A sink failure cannot undo a committed row. No relay transport,
authentication or replication is implemented in v0.2.

## Hooks

`coordkit hooks install|status|uninstall [--settings PATH]` manages Claude Code
delivery and Stop hooks. See [the hook guide](HOOKS.md) for decisions and rollback.
Default target: `~/.claude/settings.json`. Commands include an
explicit `COORDKIT_HOOK_OWNER` marker. Repeated installation is idempotent and
adds the Stop entry to older delivery installations through the same receipt.
Receipts preserve original rollback data; unrelated settings survive uninstall.

`coordkit update --reconcile-hooks` migrates owned commands after upgrades.
User edits to managed entries cause `hook_rollback_conflict`; they are never
overwritten. Lead and question hook receipts also reconcile. The public delivery
hook remains fail-open and bounded. No hooks install during package import,
`init`, `doctor`, or `update --check`.

## Services

`up --plan`, `up --apply` and `down` use the selected manager. macOS defaults to
launchd, Linux to systemd user units; `[services] manager = "systemd"` or
`"launchd"` overrides detection. Existing `[launchd]` interpreter, label and PATH
settings remain the portable job-spec inputs for compatibility.

Systemd writes service/timer pairs under `$XDG_CONFIG_HOME/systemd/user` (default
`~/.config/systemd/user`), enables the timer, and compares files and loaded
arguments/environment for drift. `SYSTEMCTL` overrides the executable in tests.
For sessions that must survive logout, the operator can configure
`loginctl enable-linger USER` separately. Installation does not change lingering.

Doctor checks managed periodic jobs' last exit status and compares a readable
job `PYTHONPATH` coordkit version with its own. Jobs installed outside the
managed label prefix are invisible unless explicitly declared in launchd
`observed_labels`. An observed job must name the same manifest and a positive
`StartInterval`; doctor checks its exit status and source version read-only.
Observation does not adopt the job, compare its full template, or include it in
`up`/`down`. Version comparison requires a readable source `__init__.py` in the
job's `PYTHONPATH`; an observed job without that evidence is red rather than a
false green.

`coordkit mcp install [--clients-file PATH] [--secret-file PATH] [--port 8767]`
installs a loopback-only service using configured credentials. Create named tokens
with `mcp-clients add` first. Installation never creates or recreates legacy secrets;
only pre-existing private legacy secrets remain supported for migration. `mcp uninstall` removes that
service and retains the token. Public transport and write enablement remain
explicit operator actions. See [MCP.md](MCP.md).

## Installation and updates

`init PROJECT --git-repo OWNER/REPO` defaults to the minimal profile. ANX resources
are provisioned only with `--profile anx`. `[anx]` and `[agentctl]` are optional;
if present their required fields are validated. `doctor` reports absent optional
integrations without requiring their CLIs.

Install an attached release wheel with pip/pipx/uv, or run `scripts/install.sh
[latest|vX.Y.Z]` for managed updates. The installer verifies the release wheel
against its `SHA256SUMS` asset. The repository defaults to
`Git-on-my-level/coordkit`; `COORDKIT_RELEASE_REPO` overrides it. A PyPI name and
trusted-publishing setup must exist before using a PyPI install command. The
release workflow has a `pypi` environment and a trusted-publishing job gated by
`COORDKIT_PYPI_PUBLISH=true`; leave it disabled until that ownership is configured.

The managed layout is `~/.local/share/coordkit/releases/vX.Y.Z`, with an atomic
`current` symlink and a shim in `~/.local/bin`. `COORDKIT_INSTALL_HOME`,
`COORDKIT_BIN_HOME`, and `COORDKIT_STATE_HOME` relocate these paths for tests.
Plain venv installs remain notify-only and print their package-manager command;
`update --adopt` explicitly enters the managed layout and refuses to overwrite
an unrelated command.

- `update --check`: release metadata and notify policy/state, no install.
- `update --apply`: verify checksum, safely unpack a pure Python wheel, smoke-test,
  write rollback evidence, swap `current`, reconcile registered hooks/services.
- `update --rollback [vX.Y.Z]`: smoke-test and reactivate an installed release.
- `update --reconcile-hooks`: reconcile registered installations without fetching.
- `update --prune --keep N`: retain current, newest N and the last rollback anchor;
  remove only version directories with an installation receipt.

`init` and applied `up` register manifests in the host state directory. A missing
registered manifest or an edited owned hook is an actionable update failure.
Updates serialize with an advisory lock. API/download requests time out after
10 seconds; staged smoke tests after 30 seconds. Failed staging never changes
the active pointer. Post-swap reconciliation failure restores its prior target.
