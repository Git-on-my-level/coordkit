# v0.2 operations and adapter contracts

Python 3.11+, standard library only, on macOS and Linux.

## Operations

[OPS.md](OPS.md) is generated from `coordkit.ops`. Bus parser arguments and MCP
schemas come from this registry; the v0.1 MCP schemas are frozen in a fixture.
The existing orchestration commands remain compatibility entry points for
installations using cards, loops, questions and lanes. New integrations should
use the small adapter interfaces rather than importing that orchestration layer.

## Bus

New records carry `v: 2` and a zero-based physical-line `seq`, assigned under the
append lock. Legacy records normalize to `v: 1` in memory. No migration rewrites
the log. Invalid complete lines are reported and represented by inert rows so
integer cursors keep their positions; malformed hold objects remain visible.
An incomplete final line is retried by tail readers and blocks appending.

Reader cursors, refs, aliases and the harvest cursor live in `state/` beside the
bus log. Old manifest-root cursors and aliases are read for migration. During the
compatibility window, inbox/wait and harvest cursors advance in both locations so rolling
back the wrapper does not replay delivered work. On re-upgrade, readers select the
greatest valid position from either location in memory; corrupt, negative and
beyond-end positions cannot hide work. Only consumption under the cursor lock
and write gate advances both copies. Unmarked harvest never writes cursors.
Mirror state remains under the manifest root. Byte
checkpoints validate inode, size and the preceding boundary before reuse.

Use repeated `--to` flags (or comma-separated names) for multiple recipients.
Each recipient gets one scalar-`to` row. `bus reply ID --from NAME TEXT` posts an
answer to the original sender and acknowledges actionable work. Identical posts
within five minutes print `DEDUPED ID`; `--force` bypasses suppression. FYI and
state latches retain their longer reminder windows.

## Live lanes and wake

Every registered lane is live until explicitly retired. There is no wake opt-in.
An addressed non-FYI post to a lane or alias wakes a non-listening live lane;
broadcasts never wake. The agentctl adapter is discovered when its executable
is available. It continues the latest execution labelled `coordkit.lane.<lane>`
with an idempotent request key and asks the resumed session to read its entire
inbox. `coordkit lane` launches add that label; other launchers opt in by adding
it. The lane name alone is not enough, because workers a lane launches carry its
name too. The continuation runs in its own process session, so waking never
bounds or cancels the resumed turn.

Rows written by another bus CLI bypass the post-append sink. Run
`coordkit wake-scan` on a short interval to apply the same policy to them; it
keeps a byte checkpoint and starts at the end of the log on first run.

`[bus] wake_debounce_minutes = 5` is the default. Bus-side `state/wakes/` stores
intent before contacting the adapter, its outcome, and a JSONL attempt journal.
Failures and unavailable adapters also hold the debounce window. A pending
record after a crash is visible and eligible for a fresh attempt after the
window. Unresumable sessions, including remote-control sessions, depend on the
delivery hook while live.

`coordkit retire NAME --to OWNER` refuses future posts with an owner redirect.
`coordkit unretire NAME` restores delivery. Aliases resolve before both actions.
Retirement state is shared by writers using the same log.

## Adapters and the relay seam

`coordkit.adapters` defines `HarnessAdapter`, `LauncherAdapter`, and
`MirrorAdapter` protocols. Built-in optional adapters cover agentctl, ANX and
Claude Code. Codex and Hermes report configuration presence only; no hook
installation is implied. Third-party adapters register the `coordkit.adapters`
entry point and are selected by name in `[adapters.NAME]`.

Core owns append locks, cursor advancement, mirror retry/dead-letter state and
wake debounce. Adapters own external commands and projections. The named relay
seam is `notify(manifest, recs)` after the append has been fsynced and its lock
released. A sink failure cannot undo a committed row. No relay transport,
authentication or replication is implemented in v0.2.

## Hooks

`coordkit hooks install|status|uninstall [--settings PATH]` manages Claude Code
delivery hooks. Default target: `~/.claude/settings.json`. Commands include an
explicit `COORDKIT_HOOK_OWNER` marker. Repeated installation is idempotent.
Receipts preserve original rollback data; unrelated settings survive uninstall.

`coordkit update --reconcile-hooks` migrates owned commands after upgrades.
User edits to managed entries cause `hook_rollback_conflict`; they are never
overwitten. Lead and question hook receipts also reconcile. The public delivery
hook remains fail-open and bounded. No hooks install during package import,
`init`, `doctor`, or `update --check`.

## Services

`up --plan`, `up --apply` and `down` use the selected manager. macOS defaults to
launchd, Linux to systemd user units; `[services] manager = "systemd"` or
`"launchd"` overrides detection. Existing `[launchd]` interpreter, label and PATH
settings remain the portable job-spec inputs for compatibility.

Systemd writes service/timer pairs under `$XDG_CONFIG_HOME/systemd/user` (default
`~/.config/systemd/user`), enables the timer, and compares files and loaded
arguments/environment for drift. `SYSTEMCTL` overrides the executable in tests.
For sessions that must survive logout, the operator can configure
`loginctl enable-linger USER` separately. Installation does not change lingering.

`coordkit mcp install [--secret-file PATH] [--port 8767]` creates a private token
if absent and installs a loopback-only service. `mcp uninstall` removes that
service and retains the token. Public transport and write enablement remain
explicit operator actions. See [MCP.md](MCP.md).

## Installation and updates

`init PROJECT --git-repo OWNER/REPO` defaults to the minimal profile. ANX resources
are provisioned only with `--profile anx`. `[anx]` and `[agentctl]` are optional;
if present their required fields are validated. `doctor` reports absent optional
integrations without requiring their CLIs.

Install an attached release wheel with pip/pipx/uv, or run `scripts/install.sh
[latest|vX.Y.Z]` for managed updates. The installer verifies the release wheel
against its `SHA256SUMS` asset. The repository defaults to
`Git-on-my-level/coordkit`; `COORDKIT_RELEASE_REPO` overrides it. A PyPI name and
trusted-publishing setup must exist before using a PyPI install command. The
release workflow has a `pypi` environment and a trusted-publishing job gated by
`COORDKIT_PYPI_PUBLISH=true`; leave it disabled until that ownership is configured.

The managed layout is `~/.local/share/coordkit/releases/vX.Y.Z`, with an atomic
`current` symlink and a shim in `~/.local/bin`. `COORDKIT_INSTALL_HOME`,
`COORDKIT_BIN_HOME`, and `COORDKIT_STATE_HOME` relocate these paths for tests.
Plain venv installs remain notify-only and print their package-manager command;
`update --adopt` explicitly enters the managed layout and refuses to overwrite
an unrelated command.

- `update --check`: release metadata and notify policy/state, no install.
- `update --apply`: verify checksum, safely unpack a pure Python wheel, smoke-test,
  write rollback evidence, swap `current`, reconcile registered hooks/services.
- `update --rollback [vX.Y.Z]`: smoke-test and reactivate an installed release.
- `update --reconcile-hooks`: reconcile registered installations without fetching.
- `update --prune --keep N`: retain current, newest N and the last rollback anchor;
  remove only version directories with an installation receipt.

`init` and applied `up` register manifests in the host state directory. A missing
registered manifest or an edited owned hook is an actionable update failure.
Updates serialize with an advisory lock. API/download requests time out after
10 seconds; staged smoke tests after 30 seconds. Failed staging never changes
the active pointer. Post-swap reconciliation failure restores its prior target.
